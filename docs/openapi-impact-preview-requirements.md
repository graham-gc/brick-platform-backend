# 需求：在 OpenAPI 同步预览中显示无法评估的引用

## 用户要解决的问题

维护测试流程的人在同步新版 OpenAPI 之前，需要知道哪些地方受影响，也要知道哪些地方 Brick 没有查到。现在，字段保留和 Schema 无法解析都可能产生空结果。两者需要不同的处理：前者在本次检查范围内没有发现问题，后者需要人工核对。

例如，商城示例用 `allOf` 把公共响应结构和订单数据组合起来。若流程断言引用了 `$.data.status`，本轮预览应告诉用户该引用因组合 Schema 无法评估，让用户能打开具体节点检查。

## 预览结果

入口沿用 **Swagger Mappings → Sync → Validate → Preview Impact**。预览针对已保存 HTTP 节点的响应变量和已启用 JSONPath 断言，按同一接口、响应状态码和内容类型比较新旧声明。

| 结果 | 判定 | 页面表现 |
| --- | --- | --- |
| **发现影响** | 旧 Schema 明确声明字段，新 Schema 的可比较结构中已没有该字段。 | 保留影响清单，可打开对应的响应变量或断言。 |
| **已检查，未发现影响** | 有实际完成的比较，且没有发现影响或无法评估项。 | 显示本次检查范围内未发现影响，并显示完成的比较数。 |
| **无法评估** | JSONPath 不受支持、接口或响应无法匹配、缺少可用 Schema、引用无法解析、路径经过组合 Schema、结构不明确，或旧版没有声明该路径。 | 单独列出流程、节点、路径、原因和可用的响应信息。若原因属于某一版契约，注明当前版或新版。 |
| **无引用可查** | 没有可纳入本次检查的已保存响应变量或启用的 JSONPath 断言。 | 明确提示没有检查对象。 |

一次预览可以同时有已检查项、受影响项和无法评估项。页面始终显示完成的比较数、受影响数和无法评估数；存在无法评估项时，提示评估不完整，即使没有受影响项。两个清单都保留节点跳转。

计数以「保存的引用 × 文档中的响应」为比较单位。同一引用可能涉及多个状态码；可以在一项比较中发现影响，在另一项中无法评估。旧 Schema 明确不包含该字段的响应不会作为删除比较对象；如果旧版所有响应都明确不包含它，则该引用报告一次「旧版未声明」。复杂 JSONPath 等与某个响应无关的原因也只报告一次。

## 同步与兼容

- 预览只读，不更新映射、接口定义或流程，也不会运行测试。
- 用户查看结果后仍可返回修改输入，或主动确认同步刚刚预览的文档；无法评估不自动阻止同步。
- 原有 `POST /api/brick/sync/preview` 保持返回受影响引用列表。新增 `POST /api/brick/sync/preview/report` 使用同样的请求体，返回 `checkedCount`、`impacts` 和 `unassessed`；页面使用详细报告。
- 本轮不解析 `allOf`、`anyOf` 或 `oneOf` 的合成语义，不新增字段类型或请求结构的兼容性判断。新文档无法解析时仍按请求错误处理，不显示成功的预览。

## 验收

1. 同一响应保留已引用的字段：检查数大于零，受影响和无法评估均为零。
2. 新版删除已引用的字段：影响清单定位到正确的流程节点、变量或断言；未变更的引用不在清单中。
3. 只有组合 Schema、无法解析的引用、缺失 Schema 或复杂 JSONPath：结果为评估不完整，显示具体原因，不显示「已检查，未发现影响」。
4. 同一预览既有字段删除又有无法评估项：两个清单和计数都可见，均可打开对应节点。
5. 没有检查对象时，显示「无引用可查」；已删除的流程或节点、停用断言不计入。
6. 预览后不确认同步，已保存的接口定义保持原样；旧预览接口仍返回原格式。
